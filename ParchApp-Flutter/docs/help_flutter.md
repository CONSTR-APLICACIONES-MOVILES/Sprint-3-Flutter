# Help (Flutter)

Help ports the FAQ and layout of `SPRINT-3-JAVA` main: `assets/data/help_faq.json` is copied from the Android asset. The local database is `parchapp-help.sqlite`; on SQLite builds with FTS4 it indexes the question and answer columns. On builds without FTS4, the same prefix matching is performed locally against the small set of records. The FAQ is initialized transactionally and never replaced by an empty or failed server response. Search is debounced for 250 ms and keeps at most 20 result sets in memory.

On Android, `MainActivity` exposes a platform channel that requires both validated Wi-Fi and a battery at or above 15%, unless charging; unknown battery state follows the Java behavior. The app then reads active `helpFaq` documents from Firestore only after the 24-hour synchronization interval and 30-minute retry interval. The local database is replaced transactionally and the preference timestamp is updated afterward. Refresh is attempted while the Help view is open, on connectivity changes and when it resumes; unlike Java's shared header registration, it does not currently run globally while other screens are open.

On iOS, macOS, web and other platforms, remote Help synchronization is disabled until an equivalent validated Wi-Fi and battery check is implemented. Bundled or previously downloaded help remains available offline on platforms supporting sqflite. Web does not currently have a SQLite implementation. The existing local Backend Firestore rules do not define access to `helpFaq`; deployed rules and data must allow the authenticated query before remote refresh can succeed. No rules are deployed or changed by this feature.
